# 白话 AI / 花花老师 — 体验评审报告（第 6 轮：整体感受）

> 评审日期：2026-08-23
> 评审人：体验达（UserExperienceArchitect）
> 评审范围：MenuBar、FloatingPanel、Pet 窗口与气泡、语音输入气泡、DesignTokens
> 评审方式：代码走查 + PET_STATE_SPEC / V0_2_BACKLOG 交叉比对

---

## 0. 总体判断

工程底子不错：Reduce Motion 适配、VoiceOver 标签、错误恢复路径、隐私提示都在。
**但"感受一般"的根源不是缺功能，而是四个体验断层：**

1. **人格不统一** —— 同一个产品里出现「白话 AI / 花花老师 / AI 老师 / 桌面老师 / 吉祥物」五种称呼，用户无法形成稳定的产品人格认知。
2. **反馈太"安静"** —— 语音输入没有音量/波形反馈，加载只有一个转圈，宠物通知只是一个 12pt 的紫点。用户不知道"它听见我了吗、它在干活吗"。
3. **交互路径有死胡同** —— 语音转写完成后没有下一步动作；宠物 Error 气泡不可点击；单击宠物要等一个双击间隔才响应。
4. **规范与实现已漂移** —— PET_STATE_SPEC 第 3 节点击规则与 PetWindowController 实际行为不一致，后续迭代会在这个分歧上继续累积混乱。

---

## 1. P0 — 直接影响"感受"的问题（建议 V0.1.1 内处理）

### P0-1 语音输入零反馈，用户不知道麦克风有没有收到声音
- **证据**：`PushToTalkBubbleView.swift:108-141`，按住说话期间只有标题文字变成「正在听…」，没有任何实时音频电平、波形或动效。`lineLimit(3)` + `minHeight: 34` 还会导致文字到达时气泡内容跳动。
- **感受影响**：按住说话是产品最高频的主动交互，"它到底听见没有"的不确定感是"体验一般"的最大来源。
- **建议**：
  - 在按住区域加实时音量电平条或呼吸波形（SFSpeechRecognizer 无法直接给电平，需从 AVAudioEngine tap 取 RMS，SpeechInputController 层已有音频管线路径）。
  - 转写文字区改为固定 3 行高度 + 内部滚动，消除布局跳动。
  - 进入 listening 时给一次短促的触觉/声音提示（NSBeep 或自定义轻提示音，可在设置中关闭）。

### P0-2 语音转写完成后是死胡同
- **证据**：`PushToTalkBubbleView.swift:125-141`，`.completed` 状态只有「清除」和「打开教学窗口」，转写出来的文字没有任何"用它做点什么"的出口（不问老师、不复制、不编辑重说）。
- **建议**：completed 状态增加主按钮「问问花花老师」（把转写文本作为 Tutor 请求发送）+ 次按钮「复制」。这是把语音功能从"演示"变成"有用"的关键一步，且 V0_2_BACKLOG 的 Follow-up Tutor 正好承接。

### P0-3 单击宠物延迟一个 doubleClickInterval，感觉"迟钝"
- **证据**：`PetWindowController.swift:741-750`，单击通过 `asyncAfter(deadline: .now() + NSEvent.doubleClickInterval)` 延迟执行，等待可能的双击。macOS 默认双击间隔约 250–500ms，用户单击后要等这么久气泡才出现。
- **建议**：二选一——
  - （推荐）把双击改为长按或右键，单击立即响应；
  - 或单击立即给出轻量预反馈（宠物轻微弹跳 + 气泡立即展开骨架），双击到达时再升级为打开教学窗口。

### P0-4 产品人格命名不统一
- **证据**：MenuBar 标题「白话 AI」、退出项「退出白话 AI」（MenuBarContentView.swift:49,141）；教学窗口叫「花花老师」；气泡自称「你的 AI 老师」；菜单项叫「我的桌面老师…」「吉祥物」（MenuBarContentView.swift:80-87）。
- **建议**：定一个对外人格名（建议「花花老师」），全量替换用户可见文案：「吉祥物」→「花花老师」，「显示/隐藏吉祥物」→「显示/隐藏花花老师」。技术命名（PetModel 等）不动。

### P0-5 规范与实现漂移：宠物单击行为
- **证据**：PET_STATE_SPEC 第 3 节规定 Idle 单击=欢迎气泡、Watching/Thinking 单击=「我正在理解当前内容」；但 `PetWindowController.swift:267-269` 的 `handleSingleClick` 在任何状态都直接打开语音操作气泡。
- **建议**：明确哪边是准的。若产品已决定"单击=语音操作"（这个决定本身合理），就更新 SPEC 并删除过时行；不要留两份互相矛盾的事实源。

## 2. P1 — 明显拉低精致感的问题

### P1-1 MenuBar 菜单：成对的禁用按钮
- **证据**：`MenuBarContentView.swift:73-83`，「打开教学窗口/隐藏教学窗口」「显示吉祥物/隐藏吉祥物」四个按钮两个永远灰着。
- **建议**：合并为动态单项「隐藏教学窗口 ✓」（NSMenuItem state 或动态 title），4 行变 2 行，菜单立刻干净一半。

### P1-2 菜单可扫读性差
- 所有菜单项无图标、无快捷键提示（仅退出有 ⌘Q）；状态信息（「当前应用：…」「内容跟随：…」）与操作按钮混排无分组。
- **建议**：操作项配 SF Symbol；信息区与操作区用分组分隔；HotKeyManager 已存在的全局快捷键要在菜单项上显示出来，否则用户永远发现不了。

### P1-3 加载状态太单薄
- **证据**：`FloatingPanelView.swift:60-70`，只有一个小转圈 + 一句文案，「取消」是无样式按钮。
- **建议**：分阶段文案（理解内容 → 组织解释 → 生成要点），超过 3s 显示「内容比较多，正在加快速度…」；TUTOR_LATENCY_BENCHMARK 已有延迟数据，可以按 P50/P95 设定文案切换阈值。

### P1-4 宠物通知触点太弱
- **证据**：`PetView.swift:66-81` 未读标识是 12pt 紫点，静止无动效；`PetTutorBubbleView` 消息 `lineLimit(2)` 在 290×132 固定尺寸气泡里截断严重。
- **建议**：未读点加缓慢呼吸动效（遵守 Reduce Motion）；通知气泡尺寸改为按内容自适应（去掉 BubbleLayout 硬编码高度，让 SwiftUI 算 sizeThatFits）。

### P1-5 状态色硬编码 RGB，无深浅色适配
- **证据**：`DesignTokens.swift:29-35`，六个状态色全部是固定 sRGB 值，深色模式下饱和度/对比度未校验；`listeningAttention = stateError` 直接把"录音中"和"错误"共用一个红色 token。
- **建议**：状态色改为 `Color(nsColor:)` 动态色或 Asset Catalog 双态色；录音红与错误红拆成两个语义 token（录音用红是行业惯例，但语义上必须分开）。

### P1-6 首次运行印象：破图占位
- **证据**：`PetView.swift:209-225`，无素材时显示 `photo.badge.exclamationmark` + 「等待透明素材」——新用户第一眼看到的是一个"坏了"的产品。
- **建议**：内置一个最低限度的官方默认形象（哪怕是单色剪影），占位图只出现在自定义素材加载失败的场景，并附「重新导入」按钮。

## 3. P2 — 长期质感与一致性

| # | 问题 | 建议 |
|---|---|---|
| P2-1 | FloatingPanel 尺寸/padding 硬编码（360×480、padding 24），未走 AppSpacing token | 面板尺寸进 DesignTokens，与气泡共享层级规范 |
| P2-2 | AppTypography 只有 13/12 两级，信息层级靠默认字重撑 | 补全 11/13/15/20 四级字阶，术语卡、标题、正文、辅助各有归属 |
| P2-3 | AppMotion 只有 2 个时长，没有缓动曲线定义 | 定义 `easeOut` 为标准曲线；入场 0.3s、微交互 0.15s 保持，补充弹簧参数规范 |
| P2-4 | 教学窗口缺历史与返回（V0_2_BACKLOG 已列 Tutor History） | 维持 backlog 优先级，建议排在 Follow-up Tutor 之后 |
| P2-5 | Error 宠物气泡（「刚才这一步没有成功。」）不可点击、无详情出口 | 单击 Error 气泡直接打开面板错误页，与 SPEC 点击表对齐 |
| P2-6 | Hover 宠物只有动画暂停，无 cursor 变化、无提示 | hover 显示一行 tooltip「单击说话 · 双击打开教学窗口」，解决双击手势不可发现 |

## 4. 值得保留的好设计（不要动）

- BubbleChrome 的 Reduce Motion 降级与 `onChange` 监听（BubbleChrome.swift:36-57）
- Push-to-talk 的 VoiceOver toggle 操作与全局 mouseUp 监听（按住说话在窗口外松开也能正确结束）
- 语音权限/云端识别的两段式 consent 文案与分流（仅本机 / 允许 Apple）
- 教学面板错误态的恢复按钮按 recoveryAction 分流（重试 vs 打开设置）
- 宠物位置跨屏幕恢复与屏幕参数变化监听
